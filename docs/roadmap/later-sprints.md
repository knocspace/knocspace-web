# F6~F10 개요

← [로드맵으로](../../ROADMAP.md)

F5 이후 계획입니다. 여기는 **개요만** 적습니다. 각 스프린트를 시작하기 직전에 F1~F5처럼 상세 문서로 풀어 쓰세요. 먼 계획을 미리 자세히 적어두면 시작할 때쯤 대부분 틀려 있습니다.

F4·F5에서 실서버에 붙은 뒤이므로, 여기부터는 새 기능마다 **백엔드 엔드포인트가 먼저 필요합니다.** 백엔드가 늦으면 해당 스프린트만 mock으로 화면을 먼저 만들고 연결은 뒤로 미룹니다 ([백엔드 연동 계약](backend-sync.md)).

|---|---|---|
| [F6](#f6--데이터베이스-표) | 데이터베이스 — 표 | P1 |

**데이터베이스를 검색·파일보다 앞에 둡니다.** 백엔드에 새 도메인(Database·Property·Row) 설계가 필요해서 리드타임이 제일 깁니다. 백엔드가 F6를 준비하는 동안 프론트가 놀지 않으려면 프론트도 같은 순서로 붙어야 합니다. 검색과 파일은 Page 도메인 위에 얹히는 기능이라 언제 해도 난이도가 같습니다.

---

## F6 · 데이터베이스: 표

**시작 전 필요** — DESIGN.md §6 작은 버튼 규격 결정 + 백엔드의 **Database 도메인 설계**(B5)

**목표** — 노션의 두 번째 축을 시작합니다. **표 하나만 제대로.**

**만드는 것**

- 데이터베이스 생성, 속성(컬럼) 정의
- 속성 7종 — 텍스트 / 숫자 / 선택 / 다중 선택 / 날짜 / 체크박스 / URL
- 표 뷰 — 헤더 고정, 열 너비 조절, 행 가상 스크롤, 셀 바로 편집
- 행 추가·삭제, 행을 페이지로 열기

**주요 작업**

- `types/api.ts` — `Database` / `Property` / `PropertyType` / `Row` / `CellValue`
- `api/databases.ts` — CRUD + `queryRows({ dbId, filter, sort, cursor })`
- `@tanstack/react-table` + `@tanstack/react-virtual`
- `features/database/cells/*` — 속성 종류별 렌더러와 편집기
- **셀을 클릭하면 팝업을 띄우지 않고 셀 자체가 편집 상태로 바뀝니다** (DESIGN.md §5)
- 격자선은 `--knoc-color-grid-*` 세 개만 사용

**완료 조건**

- 5000행에서 스크롤 60fps, 첫 렌더 200ms 이내
- 셀 클릭 → 바로 편집 → Esc 취소 / Enter 확정
- 키보드만으로 표 전체를 이동·편집할 수 있다

**끝나면** — 표로 데이터를 관리할 수 있습니다.

## F7 · 데이터베이스: 보드와 필터

**목표** — 같은 데이터를 다른 방식으로 봅니다.
**핵심 제약: 표와 셀 렌더러를 그대로 공유합니다.** 카드는 표 행의 다른 배치일 뿐이라는 원칙을 코드로 지킵니다 (DESIGN.md §5).

**만드는 것**

- 칸반 보드 — 컬럼 260px 고정, 카드 드래그
- 필터 / 정렬 편집 팝오버 (폭 380px 고정)
- 뷰 저장과 전환
- 문서 안에 넣는 인라인 데이터베이스 — 그 블록만 dense로 전환

**주요 작업**

- `features/database/board/BoardView.tsx` — 표의 셀 렌더러 재사용
- 카드를 옮기면 그룹 속성값이 바뀝니다. 드래그 중 원본은 40% 투명도로 남깁니다
- `FilterPopover.tsx` — 필드 → 연산자 → 값을 한 줄에. AND/OR는 둘째 줄부터
- BlockNote 커스텀 블록으로 인라인 DB

**완료 조건**

- 같은 DB를 표 ↔ 보드로 바꿔도 데이터와 편집 동작이 같다
- 조건 5개까지 스크롤 없이 편집된다
- 인라인 DB가 있는 문서에서 그 블록만 dense, 나머지는 comfy

**끝나면** — 프로젝트 보드를 실제로 굴릴 수 있습니다.

## F8 · 검색과 정리

**목표** — 페이지가 50개를 넘어가도 못 찾는 일이 없게 합니다.

**만드는 것**

- Cmd/Ctrl+K 검색 — 제목 먼저, "본문까지 찾기"로 확장
- 최근 문서 / 즐겨찾기
- 휴지통 — 복구, 영구 삭제, 30일 안내
- 트리에서 페이지를 드래그해 옮기기
- 트리 가상 스크롤

**주요 작업**

- `api/search.ts` — `searchPages({ q, scope, limit })`. **백엔드에 검색 엔드포인트가 필요합니다.** 없으면 mock(부분일치 + 하이라이트 위치)으로 화면을 먼저 만듭니다
- `features/search/CommandPalette.tsx` — 전역 단축키, 최근 항목, 결과 없음 화면
- 검색어 입력 250ms 지연 + 이전 결과 유지로 깜빡임 제거
- `api/pages.ts`에 `listTrash` / `restorePage` / `purgePage`
- dnd-kit으로 드래그 이동 — 2px 삽입선 + 들여쓰기 미리보기, `position` 재계산
- 자기 자손으로는 못 옮기게 차단
- `@tanstack/react-virtual` — F2에서 평평한 배열로, F6 표에서 이미 도입했으므로 그대로 얹힙니다

**완료 조건**

- Cmd+K → 두 글자 → 200ms 안에 결과, Enter로 이동
- 삭제한 페이지가 휴지통에 있고, 복구하면 원래 부모 아래로 돌아간다
- 트리 1000행에서 스크롤 60fps

**끝나면** — 문서가 많아져도 관리할 수 있습니다.

## F9 · 이미지와 파일

**목표** — 글 말고 다른 것도 들어갑니다.

**만드는 것**

- 이미지 블록 — 드래그, 붙여넣기, 크기 조절
- 파일 첨부 블록
- 업로드 진행률 / 실패 후 재시도
- 문서 아이콘(이모지 52px) · 커버 이미지

**주요 작업**

- `types/api.ts`에 `FileAsset` / `UploadTicket` 추가 — presigned URL 방식을 전제로 설계
- `api/files.ts` — `createUpload` → `uploadTo(onProgress)` → `completeUpload`
- mock은 IndexedDB + `URL.createObjectURL`. **localStorage는 용량이 부족합니다**
- 업로드 중에는 로컬 미리보기를 보여주고, 끝나면 URL로 교체
- `PageIcon.tsx` — 이모지 피커 (DESIGN.md §8에서 문서 아이콘은 이모지 허용 예외)
- `PageCover.tsx`

**완료 조건**

- 이미지를 끌어놓으면 즉시 미리보기와 진행률이 보인다
- 실패하면 블록이 실패 상태로 남고 다시 시도할 수 있다
- 새로고침해도 이미지가 보인다

**끝나면** — 문서가 문서처럼 보입니다.

## F10 · 실시간 협업

**시작 전 필요** — F5(권한), 백엔드 WebSocket 서버

**목표** — F3에서 열어둔 `useEditorDoc`에 Yjs를 끼웁니다. 설계를 지켰다면 에디터 컴포넌트는 안 바뀝니다.

**만드는 것**

- 실시간 문서 동기화
- 동시 편집
- 사용자별 커서 / 선택 영역
- 접속 중인 사람 표시
- 연결 · 재연결 · 오프라인 편집 후 병합

**주요 작업**

```bash
npm i yjs y-websocket y-indexeddb
```

- 백엔드와 프로토콜 확정 — 엔드포인트, 방 이름(`page:{id}`), 인증 방식, 데이터를 누가 보관하는지
- `features/collab/useCollabDoc.ts` — Y.Doc + WebsocketProvider + IndexeddbPersistence
- **`useEditorDoc` 안쪽만 교체.** 쓰는 쪽 시그니처는 그대로 두고, 플래그로 로컬 모드도 남깁니다
- 사용자 정보 공유 — `{ userId, name, color }`. `color`는 F2에서 타입에 넣어둔 필드입니다
- `PresenceStack.tsx` — 상단바 아바타. 3명 넘으면 `+N`
- `ConnectionStatus.tsx`

  | 상태 | 문구 |
  |---|---|
  | 연결됨 | 연결됨 |
  | 연결 중 | 연결 중 |
  | 끊김 | 오프라인 — 변경 사항은 기기에 저장돼요 |

- 재연결은 간격을 점점 늘리되 상한을 둡니다
- **저장 경로를 하나로 합칩니다** — F3의 자동 저장을 주기적 스냅샷 저장으로 바꿉니다. 두 경로가 서로 덮어쓰지 않게 하는 게 이 스프린트에서 제일 조심할 부분입니다
- 기존 문서 `content` → Y.Doc 변환 경로

**완료 조건**

- 두 탭에서 같은 문단을 동시에 쳐도 글자가 사라지지 않는다
- 상대 커서가 이름·색과 함께 보이고 선택 영역이 표시된다
- 네트워크를 끊고 편집한 뒤 복구하면 양쪽 변경이 모두 남는다
- 연결 상태가 항상 정확하게 표시된다
- 저장 경로가 하나뿐이다
- E2E — 브라우저 두 개로 동시 편집 1개, 오프라인 → 복구 병합 1개

**끝나면** — 여러 명이 한 문서를 동시에 편집합니다. **제품 완성.**
